01 Data Structures
Arrays
  • Fixed or dynamic size; contiguous memory
  • O(1) access by index, O(n) search (unsorted)
  • O(n) insert/delete (due to shifting)
  • Best for: random access, iteration
Linked Lists
  • Nodes with data + pointer to next (or prev)
  • O(1) insert/delete at head; O(n) elsewhere
  • No random access — O(n) traversal
  • Types: Singly, Doubly, Circular
Stacks & Queues
  • Stack — LIFO: push, pop, peek in O(1)
  • Queue — FIFO: enqueue, dequeue in O(1)
  • Deque: insert/remove from both ends
  • Priority Queue: highest priority served first
Key Interview Insight

Stack → function call stack, undo history, bracket matching. Queue → BFS, job scheduling, print spooling. Know which to use instantly.

Trees
Binary Tree BST — O(log n) avg AVL / Red-Black (balanced) Heap (min/max) Trie (prefix tree) Segment Tree B-Tree (disk storage)
Tree Traversals
  • Inorder (L→Root→R) — sorted output for BST
  • Preorder (Root→L→R) — copy a tree
  • Postorder (L→R→Root) — delete a tree
  • Level-order — BFS, shortest path
Graphs
  • Directed / Undirected; Weighted / Unweighted
  • Represented as: Adjacency List or Matrix
  • BFS → shortest path (unweighted)
  • DFS → cycle detection, topological sort
Hash Table
  • Key → hash function → index in array
  • Average O(1) insert, delete, lookup
  • Collision handling: Chaining (linked list) or Open Addressing (linear/quadratic probing)
  • Load factor: # items / capacity — keep below ~0.7 for performance

02 Algorithm Analysis
Big-O Notation

Describes worst-case growth rate. O(1) < O(log n) < O(n) < O(n log n) < O(n²) < O(2ⁿ) < O(n!). Always reduce constants — O(2n) = O(n).

Searching
  • Linear Search — O(n), works on any array
  • Binary Search — O(log n), sorted arrays only
  • BFS — shortest path, level-wise exploration
  • DFS — deep-dive, uses stack/recursion
Divide & Conquer
  • Split problem → solve subproblems → merge
  • Merge Sort, Quick Sort, Binary Search
  • Master Theorem: T(n) = aT(n/b) + f(n)
  • Great for parallelism & recursion problems
Dynamic Programming
  • Optimal substructure + overlapping subproblems
  • Top-down: Memoization (cache recursion)
  • Bottom-up: Tabulation (fill table iteratively)
  • Classic: Knapsack, LCS, Fibonacci, DP on grids
Greedy Algorithms
  • Locally optimal choice at each step
  • No backtracking; not always globally optimal
  • Classic: Dijkstra, Prim, Kruskal, Huffman
  • Proof required: show greedy choice is safe
Graph Algorithms — Must Know

Dijkstra — shortest path, non-negative weights, O((V+E) log V).
Bellman-Ford — handles negative weights, O(VE).
Floyd-Warshall — all-pairs shortest path, O(V³).
Kruskal / Prim — Minimum Spanning Tree.

Recursion

Define base case first. Think: what's the smallest valid input? Space is O(depth) due to call stack.

Two Pointers

Fast + slow pointer tricks for linked lists (cycle detection) and sorted array problems (pair sum).

Sliding Window

Efficient O(n) technique for subarray/substring problems. Expand right, shrink left on condition.

03 Database Management
RDBMS Core
  • Tables (relations), rows (tuples), columns (attributes)
  • Primary Key — uniquely identifies a row
  • Foreign Key — links two tables (referential integrity)
  • Constraints: NOT NULL, UNIQUE, CHECK, DEFAULT
SQL Essentials
  • SELECT, FROM, WHERE, GROUP BY, HAVING, ORDER BY
  • JOINs: INNER, LEFT, RIGHT, FULL OUTER, CROSS
  • Aggregates: COUNT, SUM, AVG, MAX, MIN
  • Subqueries, CTEs (WITH), Window functions
ACID Properties
  • Atomicity — all or nothing
  • Consistency — valid state before & after
  • Isolation — transactions don't interfere
  • Durability — committed data survives failure
Normalization — Quick Reference

1NF — Atomic values, no repeating groups.
2NF — 1NF + no partial dependency (every non-key column depends on whole PK).
3NF — 2NF + no transitive dependency (non-key columns depend only on PK).
BCNF — Stronger 3NF; every determinant is a candidate key.

Indexing
  • Speeds up SELECT; slows INSERT/UPDATE/DELETE
  • B-Tree index — default; range queries
  • Hash index — exact match only
  • Composite index — column order matters!
  • Covering index — satisfies query without table lookup
Transactions & Locking
  • BEGIN / COMMIT / ROLLBACK / SAVEPOINT
  • Dirty read, Non-repeatable read, Phantom read
  • Isolation levels: READ UNCOMMITTED → SERIALIZABLE
  • Deadlock — circular dependency; DB auto-detects

CAP Theorem
Consistency — all nodes see same data Availability — every request gets a response Partition Tolerance — works despite network splits

A distributed system can guarantee at most 2 of 3 simultaneously. Most systems choose CP (e.g. HBase) or AP (e.g. Cassandra).

Query Optimization

Use EXPLAIN / EXPLAIN ANALYZE. Avoid SELECT *. Filter early with WHERE. Use indexes on join/filter columns.

Stored Procedures

Precompiled SQL blocks stored on the server. Reduces network traffic; reusable logic; can accept parameters.

Views & Triggers

View — virtual table (saved query). Trigger — auto-executes on INSERT/UPDATE/DELETE events on a table.
